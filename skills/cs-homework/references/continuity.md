# 当前范围、工具与跨聊天交接

所有入口都以当前人类请求为准。接手时读取已有普通笔记、README、交接及实际文件；`.coursework/handoff.md` 和版本旁件只是可发现的记录位置，不是必需格式。恢复当前目标、要求来源、已确认决定、进度、证据位置、原样待回答问题和下一步；历史请求与范围是背景，不能重新授予权限。

先核对当前要使用的代码、输入、命令、输出与产物。记录称已完成但文件缺失或内容不符时，说明实际差异与影响；真实证据充分而内部状态、ID 或阶段登记缺失时直接继续，不补阶段、不空跑。证据不足时只补查当前范围内的必要事实，或标为未验证；来源或代码变化按实际影响处理，不把未知当作已变或有效。保留旧证据与有用决定，外部结果如实标明提供者和已知条件。

可选 `coursework.py resume --workspace <目录>` 读取旧结构化检查。无状态、未知格式或不完整状态时，它保留原文件并提供实际文件清单，不能自动理解笔记或认证输出；Agent 直接阅读仍可继续。旧助手不能接受的格式不妨碍正常工具工作；保留原内容，不以新建统一状态覆盖。新的记录可沿用现有普通笔记并保护用户修改，无需引入统一字段、内部 ID 或登记 API。

## 写入与本地 Git

本次授权写入时，使用普通工具也自动建立或沿用本地 Git；新建独立作业目录先建立仓库，保存计划、阅读记录等有意义进展后提交本次相关文件。首次写入前核对已有文件、暂存与未暂存修改，按需保留可恢复原文；提交限定本次路径并保留原暂存区与无关修改。不能把调用旧保存脚本当成获得 Git 保护的必要条件，也不能只因已有修改就全部跳过保护。Git 操作失败时保留成果及诊断，明确未提交；显式只读分支不初始化或提交。

已有用户暂存内容时，仍提交可明确归属本次的新笔记、恢复依据及其他独立成果。先保存原暂存 diff，逐个确认自有路径后用 `git add -- <本次路径>` 和 `git commit --only -m <说明> -- <本次路径>`，再核对原暂存 diff 未变；避免无路径的提交或批量加入整个目录。预先已有用户修改的源码保持在提交外，其本次改动可保存独立补丁或输入快照作为证据。保护原暂存区不等于放弃所有本次成果提交；无可独立提交路径或 Git 实际失败时才如实说明限制。

## 一项人类任务

在可读记录中保留本次整体请求与范围。选用旧结构化助手时，其 `request` 和 `scope` 表达同一项任务；子步骤、命令用途和补跑理由写入 `basis`、`note` 或普通说明。当前任务允许的常规工作连续推进，达到用户检查点时停在该点。只有人类确实改变或收窄任务时才更新范围；不能恢复旧字段来绕过代码会话或预算确认的范围检查。

完成依据是本次真实要求、交付物与必要检查均已完成。已有代码、有效验证和实际语义复核足够时直接交付，不为同步一个内部状态标记再发起空的 `code-step`、新会话或重复执行。保留已发生的失败/拒绝，准确说明尚存的记录限制。实现已授权时失败可带原始证据返回代码修复；范围只有运行、分析、报告或检查时，必要代码修改仍等待具体范围决定。

结果来源与变化按 [结果有效性](results.md) 核对；执行与写入遵守当前请求、上述 Git 边界和相关行为说明。需要旧助手的字段与限制时才读 [共享运行约定](runtime-contract.md)。默认长实验询问阈值为三十分钟，先试跑估时，超预算等待真实回复；它不是硬超时。保存的完成标记不证明证据当前有效。个人思考的历史状态与当前依据有效性分开；pending、mixed、无回复或无登记本身不阻塞恢复与验收，仍须比较实际采用内容及受影响依据，不伪造接受或丢弃历史。

继续写报告时，读取当前正文、普通修订记录和独立反馈，按 [课程语言方法与局部案例](report-prose.md) 继续起草或修订，按当前位置检查句内至段间的必需衔接及必要提示，处理实际缺口并回读受影响内容；旧稿的语言通过标记不替代当前判断。完整报告实质修订后沿 [独立审阅的修订与复审](../../cs-homework-report-review/SKILL.md) 按问题继续，准备结束时重新独立阅读全文。只有源码、局部修改、明确保留项及只给建议的限制仍按本次请求执行，不补内部 ID 或思考接受记录，不自动重跑实验。

## 本机工具提示

开始新作业或必要工具不可用时，从**当前已加载的 cs-homework Skill 位置**查找可选的 [local-tools.json](local-tools.json)。它只存在于个人安装副本，是本机路径提示，不是可移植包的依赖。直接使用七个行为时同样从相邻 `cs-homework/references/` 定位。没有该文件就调查当前可用工具，不要求学生重复说明可自行读取的环境事实。

实际使用前重新检查解释器/编译器/渲染器是否存在，执行其版本命令；检查所需缓存目录、字体配置及绘图环境。路径失效时寻找实际可用替代并说明具体缺项，不能凭保存版本声称工具健康，也不自行安装软件。将验证过的路径用于既有 literal argv/compiler/renderer 字段，提示中的 `env` 只传给子进程；不修改全局 PATH 或宿主配置。现有执行记录继续保存真实工具身份和环境。

## 受阻或分次继续

本次已授权写入的任务，在等待实质决定或停止前，把以下实际内容保存到作业内的普通记录（可沿用 `.coursework/handoff.md`）：

- 当前人类请求与授权范围、要求来源、已确认决定；具体诊断、实际/预期值和证据路径（已有 ID 可保留）。
- 已完成的独立工作及交付位置；仍受阻的部分。
- 发给用户的**原样待回答问题**、推荐处理与依据，明确哪些权限/回答尚未取得。
- 下一步，以及需要真实决定后才可执行的动作。

可以用 `handoff --workspace <目录> --input <目录外JSON>` 保存一份由你写好的 Markdown。输入为 `{"request":"实际当前请求","scope":{"goal":"当前目标","authorized_behaviors":["report"]},"note_path":"目录外Markdown路径"}`。正文由你判断和撰写，命令不生成诊断、不解析授权，也不修改 `state.json`。它在写前用 `git.begin_task` 取快照；原交接文件已存在用户未提交修改时保存 `handoff-0001.md` 等新版本，保留原字节与暂存区，仅提交明确的本次交接文件。已有结构化上下文的 `resume.handoffs` 列出这些路径和实际哈希；无状态时直接阅读文件即可，不必补做规划。

也可依同样 Git 约定直接写普通 Markdown。不得覆盖链接或已有未提交修改；版本旁件与旧文都要可发现。获得真实回复后，用新交接说明实际决定及仍有效的下一步，明确替代哪条旧问题，保留历史。未得到回复时维持待决定；待确认的预算或修复权限不自动变成接受。

**验收**先复用有效证据；普通验收因缺项、变化或疑点需要定向运行时，按当前授权说明具体证据缺口，用普通工具或可选执行助手保存真实事实并遵守预算，不能因验收扩展实现/报告修改或额外实验；必要编译检查使用独立输出并保留原稿。详见 [验收行为](../../cs-homework-check/SKILL.md)。

**显式只读验收、禁止执行或只给语言审校建议**：按当前明确限制仅阅读并在聊天中给出发现和建议，缺证据保持未验证。只有选用旧结构化助手时才设置对应 `read_only: true` 或 `report_mode: review` 字段；这不是普通阅读的登记前提。可读取实际文件和全部交接；不执行作业程序、分析脚本或编译，不生成文件、导入结果、保存接受/审阅记录、更新状态或操作 Git。即使授权列表仍包含历史的 `run/analyze/report/code`，这些明确限制仍优先；旧状态不代替当前输入。保留辅助入口在副作用前检查当前范围。`check`、`review-prose` 等只读核对可用；`review-report` 属于可写报告流程。普通验收的必要定向补检仍可用当前 `check` 与相应执行授权，按前述约定处理。

## 外部 Skills

本项目维护八个 Skills 与标准库伴随脚本。报告写作与修订的默认完整语言方法、依赖及缺口处理以 [报告语言编辑](report-prose.md) 为准；其他活动按实际需要选用外部方法，只编程等独立任务不要求 Humanizer 或完整报告工作流。使用外部 Skill 前，先读其当前版本的 `SKILL.md`、frontmatter 与 `agents/openai.yaml`（如有），核对是否允许模型自主调用；`disable-model-invocation: true` 或 `policy.allow_implicit_invocation: false` 的入口留给用户显式调用，不能由总入口自动启动。当前可用目录与调用限制优先于旧参考表。TDD 是课程行为的可选方法，不是所有作业的前置阶段；不使用 superpowers。
