# Native edits, original bytes and real execution

Use normal small patches in the actual assignment. Keep a readable record of the current request/scope, original content and Git boundary, diagnoses, fixed independent expectations, attempts, exact run evidence and remaining work. Neither these helpers nor legacy code sessions are prerequisites.

Before the first write, inspect tracked clean/dirty, staged/unstaged and untracked files. Preserve original bytes for files being changed, existence for new files, and relevant staged/unstaged binary patches (or index blobs). Verify the saved original bytes and staged/unstaged boundary are readable before the first edit. If an optional helper or interpreter fails, use ordinary byte-copy and Git tools and verify the preserved content before writing. If preservation is still unavailable, pause edits to that file and continue independent work; a reconstructed original after editing is not a before-edit backup. Preserve unrelated content and the existing index. `begin_task` inventories dirty paths only: it is not a backup. Keep its returned snapshot for conservative `checkpoint` calls; dirty preexisting files stay outside automatic commits. Never retake the task snapshot after edits to relabel user content as task-owned.

## Optional mechanical helpers

`python <cs-homework>/scripts/coursework.py protect-edits --workspace <assignment> --input <request.json>`

The agent may prepare a small input with `request`, current `scope` (`goal`, `authorized_behaviors`), and `paths`: exact relative files about to change. Default `role: code` requires code authorization. For analysis scripts or report sources, `role: analyze` or `report` requires that current behavior; this grants no implementation repairs. The receipt retains original bytes (including dirty and untracked files), absence of new files, dirty paths, HEAD/status, staged/unstaged binary patches and exact snapshot paths. Ordinary copying plus Git inspection can preserve the same facts. Restore only deliberately after inspecting current work; never automatically reset or overwrite later user changes.

`python <cs-homework>/scripts/coursework.py capture-run --workspace <assignment> --input <request.json>`

Input is current `request`, `scope` and `execution`: literal `argv`, relevant `source_paths`, optional `input_paths`, `stdin_text` or `stdin_path`, `cwd`, `env`, `output_paths`, independent `expected`, `purposes` (`correctness`, `example`, `experiment`) and actual `basis`. `dependency_coverage` can state complete/partial/unknown plus an actual inspection note. The optional execution `role: analyze`/`report` (top-level) supports authorized calculations/compilation, not implementation repair. Default run role accepts run authorization or code correctness checks. Records preserve actual source/input bytes before and after, raw streams, exit, environment identity, time and outputs. Exact receipts live under `.coursework/native/`; no plan, state, result registration or auto commit is created. This helper executes once; an exit-zero process alone does not prove correctness, dependency completeness or semantic validity. Inspect records and actual files before reuse.

For long work, set `execution.requires_trial: true`, a short `trial` overriding argv/inputs and `workload_units`, full `execution.workload_units` and `budget_seconds`. An explicit trial stdin replaces the full stdin, including a switch between text and file. Supply a separate `trial.expected` when an independent trial answer exists; otherwise its correctness stays unverified, and the full answer applies only to the full run. The helper captures full source/input and executable/environment identity before the trial and checks it afterward. Trial failure or drift stops; an estimate above budget returns `awaiting_confirmation` without starting the full run.

After an actual user reply, invoke with the same request, scope, role, execution, trial and budget/estimate conditions, `confirmation_of` naming that receipt and `confirmation` quoting the raw reply with its actual provenance. The helper compares those fields and the saved bytes/identity before continuing; changed tasks or conditions need fresh checking and estimation. Older pending receipts lacking this baseline remain readable but need a fresh trial. Field equality cannot interpret natural-language scope or authenticate a human reply; silence or an invented reply grants no permission. Keep budget and no-progress decisions in readable notes when using ordinary tools.

## Diagnosis and recovery

Preserve teacher examples and independent expected answers. Reproduce actual failing input/output/exit first, distinguish environment/input/oracle/implementation causes, make one targeted small repair, then run the original failure and necessary regressions. For each problem keep the diagnosis, prediction, diff, actual result and progress assessment. After three targeted repairs without substantive progress, save all three versions and diagnostics, pause that problem and ask how to continue; complete independent work. Cosmetic error changes, new sessions or renamed problems do not reset this count.

The legacy `code-start`/`code-step` APIs remain optional for an existing fixed-suite session. They preserve earlier receipts and replacement-file behavior but do not control normal editing or continuation. Read their CLI/runtime code only when deliberately continuing that legacy API. The current readonly/advice guard applies before all retained helper mutations.
