# 课程报告

显式只读、禁止执行或仅报告建议统一遵守 [当前范围的只读边界](../cs-homework/references/continuity.md)：先整理当前范围，仅阅读和在聊天中反馈；旧授权不允许分析、编译或任何作业、状态与 Git 写入。

先读共享的 [当前范围、工具与跨聊天交接](../cs-homework/references/continuity.md)，恢复时实际读取作业内诊断、原样待回答问题和已完成部分；必要编译/绘图工具从当前安装提示定位并重新验证。授权写报告而受阻时，在作业内保存交接再停止；只给审校建议时保持只读。

直接接手本次请求和原作业目录，实际阅读已有题目、代码、结果、思考与格式材料。已有材料足够就写报告，不要求先运行规划、实现或分析。当前请求决定本次范围；同一项人类任务内的内部补跑、作图和编译保持同一整体请求与范围，在普通记录中说明子步骤用途。人类确实改变目标时更新范围，不能恢复旧授权来通过检查。

**只审阅或只给建议**：直接使用 [cs-homework-report-review](../cs-homework-report-review/SKILL.md)。写作与修订先读 [共享报告质量标准](../cs-homework/references/report-quality.md)。语言是第一优先级，具体语言要求是硬性通过条件；总篇幅和各部分分配按任务情境判断。

**逐项附注句执行共享标准的删除硬规。** 发现即整句删除，不考虑其他任何条件；保留、改写保留、挪位或补入同类说明均属违规。下文编辑取舍及 Humanizer 的信息保留要求不能豁免该规则。

**新写、续写和修改已有报告**：起草及修订时即读 [课程写作、完整语言编辑与局部案例](../cs-homework/references/report-prose.md)，按共享标准的删减优先顺序处理不清楚的内容，落实连续展开、必需衔接和学生口吻，再读取并执行选定 Humanizer 完整方法。允许不妨碍理解的适度简略，可选内容优先省去。只有核心内容不能删除且不补便无法理解时才补必要解释，少一个承接词或对象提示时可直接补齐。默认不写局限讨论或验证状态尾句；明确的课程与保留要求优先。既有思考按其实际内容和依据继续，不因缺旧接受登记阻塞编辑。完整改稿另由独立 Agent 按审阅入口检查。

按共享交接约定读取普通记录、实际结果与关联图表，结构化状态及 `resume` 是可选辅助。读 [结果来源](../cs-homework/references/results.md) 与 [分析交接](../cs-homework/references/analysis.md)。保存的 completed 标记不能替代真实文件与证据检查；已有 ID 可保留但不要求先登记。外部数据的提供者、来源和核验状态留在工作记录，不冒充本次新测量，也不把这些状态逐项附在报告正文。

实际读课程要求与主要代码、结果，确认正文回应本次任务。图表、表格和正文采用同一结果版本，核心方法与结果的明显矛盾按已有依据简洁处理。来源与未确认事项留在工作记录，不要求报告逐项自证。

文章与段落结构首先服从用户、任务书及相关资料的明确要求。没有结构要求时，根据当前作业安排问题、方法、实现、验证、分析与思考等必要内容；不强制摘要、研究背景、创新点或固定章节。总篇幅与各部分篇幅按共享标准结合要求、任务性质、规模和交付重点安排，参考其中的情境数字，不把示例页数当配额。讲清主要方法和运行结果，重要图表自然交代用途与观察；额外实验、源码和日志不因已经存在就详写进正文。

**格式参考只提供格式。** 从 LaTeX 样例中提取字体、字号、页边距、行距、标题外观、页眉页脚及图表样式等，并记录实际采用项。样例的正文、章节、段落顺序、论点和数值均不是报告内容或结构来源，即使其内容看起来像完整报告。章节组织单独从当前任务决定，再应用样式。

报告以学生本人回顾已完成作业的立场说明实现、选择、观察和判断，按共享标准在合适位置自然使用“我”，与概念、公式及常规过程的客观说明结合。围绕实际逻辑与观察自然展开，不为了使表述更精准而补充限定和说明。可省的猜测或细节直接省去，不能编造调试、查阅、学习或实验经历。

**个人思考自主形成。** 按 [有依据的个人思考](../cs-homework/references/reflection.md)，根据本次要求、实际实现、真实结果与原理形成判断，可融入方法、结果和取舍。读取并尊重已有真实人类判断；缺少回复或接受登记不阻塞成稿、续写或验收，不例行采访。报告只有学生作者，实际 Agent 完成的作业过程可据实叙述，不能虚构困难、感受或经历。仅有影响当前判断的实质歧义时提出具体问题，继续独立部分。

普通笔记保留采用段落的依据与位置，旧问题、原回复、推荐及真实接受历史原样可读。pending、mixed、未登记本身不影响当前有效报告完成，也不伪造接受、清除旧链接或重写历史。相关代码、数据、要求变化时比较受影响的具体论断，必要时修正文段并更新语言、审阅和构建证据；无关有效内容继续使用。

成稿后默认按 [完整语言编辑与课程适配](../cs-homework/references/report-prose.md) 实际读取并执行选定 Humanizer 方法，对照原稿和依据检查表达与技术含义。完整报告依 [独立审阅的修订与复审](../cs-homework-report-review/SKILL.md) 按实际问题连续改进，准备结束时作新的独立全文阅读，不能把修完已知意见当作全文通过。编译看页仅在本次交付范围内执行，短段和仅源码不扩成完整流程。来源、固定版本和实际效果见项目的 `docs/skill-references.md`；个人安装按共享指导定位完整依赖，不以本地摘要代替。

缺少报告必需的运行证据时，可以补跑**已有代码**，或从有效结果生成必要图表。先实际读取程序和要求：补的究竟是哪项缺失证据、确切已有输入/参数是什么。按 [真实运行](../cs-homework-run/SKILL.md) 用普通工具或可选 `capture-run` 保存独立预期、依赖字节与预算事实，在普通记录中说明对应任务要求和精确补跑内容；选用旧 `run` 时才使用其 `execution.report_support.basis` 字段。题目本来要求但缺失的实验可补；额外性能比较、参数扫描或实现修改需要当前已授权范围或用户的具体范围决定。泛称“为了报告”不能扩展范围。环境、输入或预期有问题先定位；必要实现修复未授权时说明问题与推荐处理，继续不依赖它的报告部分。

通常交付自包含、可继续编辑的 LaTeX 项目及真实编译 PDF；用户只要源码时按请求交付。使用实际可用的 LaTeX 编译器，不以其他 PDF 生成方式替代 LaTeX。需要 PDF 工具/Skill 时遵守其当前工具约定，包括适用的 authoring marker。先调查可用编译器、字体与渲染器；保持环境设置局部，保留日志。编译失败或引用未解决时交付源码与具体诊断，不能沿用旧 PDF 充当本次成功。

准备写入与编译时读 [稳定报告项目与实际构建](../cs-homework/references/report.md)。直接编辑原作业中明确的主项目和主文件；新项目也保持稳定位置。首次编辑前识别 Git 状态并保留本次将改原文的可恢复字节，沿用共享编辑保护；辅助工具或解释器不可用时先用正常文件复制保护，再编辑。普通笔记、已有数据和图表足够继续，不以报告、结果或分析 ID 为前提。可选 `compile-project` 复用编译、日志和页面机械记录，也可用普通编译命令保存同等事实；不复制整份源码到新版本目录。

编译后读实际 PDF，并将每一页渲染成图像打开检查：文字、公式、中文字符、图轴单位、图例、表格、代码排版、页码及交叉引用均须清楚，没有遮挡、越界或 `??`。只读日志或提取文本不能完成版面检查。先确认语言硬性要求和详略实际通过，并按需核对题目及核心内容后，在易读记录中保存具体意见、改动及全部页面路径；编译成功只是待审阅，不是完成。出错则修正当前报告或派生计算，保存失败证据并重编译、重渲染，通常检查最终全部页面，不能把正文问题归咎为课程代码错误。同一问题三次有针对性修复无进展时保存现场并暂停该部分，继续独立工作。

交付可编辑项目与当前 PDF，准确说明范围、来源及仍失败/待更新/未验证的检查。源代码、数据、要求或依赖分析改变时报告会待更新；只更新受影响部分。自动 Git 只提交本任务输出和证据，保留已有用户文件及暂存内容。完成报告不自动启动额外实现、实验或完整验收。
