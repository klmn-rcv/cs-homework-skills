# 独立课程报告审阅

先读当前请求和 [共享报告质量标准](../cs-homework/references/report-quality.md)，按 [当前范围](../cs-homework/references/continuity.md) 接手已有报告。**语言是第一优先级，共享标准中的具体语言要求是硬性通过条件。** 不够周全但能自然读懂的表达可以保留，疑点优先删减可选内容，仅在核心内容不能删除且不补便无法理解时补说明。默认不写局限讨论，不因“更严谨”追加边界尾句。

**逐项附注句执行共享标准的删除硬规。** 发现即判违规并要求整句删除，不考虑其他任何条件；保留、改写保留、挪位或补入同类说明均属违规，有残留就不能通过。审阅者自己的改文同样执行，下文编辑取舍及 Humanizer 的信息保留要求不能豁免该规则。只读审阅交付删除意见，不写文件。

**只审阅或只给建议**：只读并在聊天交付反馈，不改作业、分析、编译、渲染、登记状态或 Git。用已有 PDF 或页图检查页面，没有或未能查看的部分说明未验证；需要 Git 观察时用 `git --no-optional-locks`。组合请求的其他权限不自动扩大本次审阅。

**独立执行**：完整报告由另一名 Agent 或独立新会话审阅。模型沿用宿主当前配置，用户有明确选择时按其选择，不绑定厂商或型号。只提供当前请求、指导和必要材料位置，不提供作者自评、旧缺陷清单、理想改文或其他人的结论。另一个执行上下文才构成独立审阅，不能由作者换 Skill 名称冒充；单独接手审阅的 Agent 可直接承担，缺少独立条件时如实说明。

## 阅读与反馈

首次接手先读课程要求、报告全文及报告中的图表，以有课程基础、不了解本次代码的老师或助教身份连续阅读。此时暂不查代码、原始结果、日志或作者解释，先判断正文能否自然读懂。随后仅沿核心内容的实际疑点查必要依据，不能因从代码补懂便认定原文已清楚，也不默认逐项追查所有数字和限定条件。

实际读取 [课程语言指导及局部案例](../cs-homework/references/report-prose.md)。按共享标准从句内到跨段检查反复附注、必需衔接、对象转换、内容来由及学生口吻。概括转向观察时，看当前文字是否交代为什么采用这个例子、时点或对象；前文出现过仍按读者当前位置判断。一个词或短语就能补足承接时可直接建议，不另加背景段落。可省内容导致理解负担时优先删去，不为追求周全增加解释。

拟议改文和原稿采用同一语言标准。建议删减、改写或补词后，连读前后句，确认推进自然、对象仍清楚、没有新添附注。修正事实时也须这样做。已经自然、有用的说明保留，不机械删解释、否定句或连接词。局部案例只校准判断，不限定检查范围或提供固定句式。

核对是否回应本次课程要求，核心方法与结果是否有明显矛盾，结构及总篇幅、各部分分配是否符合任务情境。必要依据足以确认核心错误时简洁指出改法，不把一般课程报告当学术论文精密审稿，不主动寻找理由增加局限。涉及个人思考或未来内容时读 [reflection.md](../cs-homework/references/reflection.md)，看是否由学生回顾本次实际认识，不例行要求展望、采访或新实验。

按交付范围查看现有页面的可读性和引用，不以留白优化或可选排版偏好取代正文审读。反馈给出具体位置、必要原句、阅读影响和简洁修改方向。区分必须处理的语言或核心内容问题与可选措辞，不能因为技术正确、总体能猜懂或已经改过多轮而放过明显语言问题。未查看的代码、数据或页面如实说明即可，不要求把这些说明写回报告。

## 修订、复审与结束

已授权修改时，衔接 [cs-homework-report](../cs-homework-report/SKILL.md) 处理反馈，无需每轮重复批准；仅建议时停在聊天反馈。作者按当前要求与上下文修改，默认先删减可选内容，核心理解确有需要才补充。然后由独立审阅者实际读修订稿及受影响上下文，同时找新问题，不能只接受作者声明或把旧问题修完当作全文通过。

按实际剩余问题继续“审阅—修订—复审”，不设一两轮上限，也不为凑轮数重写自然段落。准备结束完整报告的实质修改时，另由新的独立上下文重新读最终全文和图表，仍先正文后必要依据，不给旧问题清单或作者通过自评。**结束要求是当前语言硬性条件通过、课程要求和核心内容得到回应、详略合适及交付范围内页面可读。** 各项打勾、已花时间或某项技术检查通过不能代替实际判断。

仅源码、短段及连贯节选按本次范围检查，不扩成完整报告。相同问题连续三次针对性修复无进展时保留原稿、当前稿、意见与诊断，说明剩余影响并继续独立部分；不把三次当整篇报告轮数上限，不换名称清零或把未通过改记通过。只读时这些信息在聊天交付。
